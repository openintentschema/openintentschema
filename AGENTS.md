# AGENTS.md

Guidance for coding agents and new contributors. Start with [README.md](README.md).

## What this repository is

The Open Intent Schema (OIS) standard: specification, JSON Schema, examples, conformance
fixtures, profiles and the website openintentschema.io. Software lives in the sister repository
[openintentschema/tools](https://github.com/openintentschema/tools) (the `ois` command, PyPI
package `ois-tools`), usually checked out next to this one; it copies schema, examples and
fixtures from here.

The standard is vendor-neutral: nothing here may depend on, name or favour a product or vendor.
Vendor data goes into `extensions` under a reverse-DNS namespace, industry rules into profiles.

## Commands

```bash
uv run fixtures/generate.py           # regenerate fixtures and manifest after changing generate.py
uv run fixtures/generate.py --check   # what CI runs
cd site && npm ci && npm run build    # website; fails on a broken internal link
```

`.github/workflows/checks.yml` shows how the examples are validated with ajv.

## Rules for changes

- Data model, integrity rules, schema, conformance levels or passport format: an RFC issue first,
  then one pull request that updates specification text, Appendix A/B, `schema/`, `examples/`,
  `fixtures/generate.py` and the change history table of the specification together.
- Never edit fixture JSON by hand; change `fixtures/generate.py` and regenerate. The one input
  that cannot be generated, the keyless Sigstore bundle `fixtures/sigstore/passport.sigstore.json`,
  is recorded by `.github/workflows/sigstore-fixtures.yml` (run by hand on `main`, artifact
  downloaded and committed); record it again when `generate.py --check` says so.
- The website's specification, community, conformance and profile pages are generated by
  `site/scripts/sync-content.mjs` and not committed; edit their sources.
- The guides in `site/src/content/docs/` (`getting-started`, `approve-intents`, `record`,
  `build-a-passport`, `sign`, `privacy`, `develop/tools`) describe the `ois` commands; update
  them when a command changes.
- Versioned URLs on the site (`/schema/v0.1/`, `/passport/v0.1/`,
  `/methods/basic-intent-coverage/v0.1/`) never change meaning; a correction is a new version.
- English everywhere. RFC 2119 keywords in capitals only where normative.
- Use the newest released versions of tools, libraries and GitHub Actions; pin Actions to a
  commit SHA with the version as a comment. Dependency updates are made by hand, without bots.
- Commits: one line, with DCO sign-off: `git commit -s -m "<what changed>"`.
