# site

Source of the website [openintentschema.io](https://openintentschema.io), built with
[Astro Starlight](https://starlight.astro.build/) and published to GitHub Pages by
`.github/workflows/site.yml` on every push to `main` that touches `site/` or `schema/`.

```bash
cd site
npm ci            # Node.js version in .nvmrc
npm run dev       # local preview at http://localhost:4321
npm run build     # static site in dist/, then publishes the schema (below)
```

## Structure

The site has three sections, shown as tabs (`src/components/Header.astro`) and set up with
`starlight-sidebar-topics` in `astro.config.mjs`: Documentation, Specification and Community. The
look follows specification sites such as the Model Context Protocol's: monochrome, Inter served
with the site (`src/styles/custom.css`), the specification split into one page per section.

| Pages | Source |
| --- | --- |
| `/`, `/getting-started/`, `/approve-intents/`, `/record/`, `/build-a-passport/`, `/sign/`, `/privacy/`, `/learn/…`, `/develop/…` | `src/content/docs/`, written for the site |
| `/passport/v0.1/`, `/methods/basic-intent-coverage/v0.1/` | `src/content/docs/`, written for the site |
| `/specification/…` | `../specification/ois-spec-v0.1-draft4.md`, one page per `##` section |
| `/community/…` | `../GOVERNANCE.md`, `../MAINTAINERS.md`, and `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md` in `../.github/` |
| `/conformance/`, `/profiles/…` | `../fixtures/README.md`, `../profiles/**/README.md` |
| `/schema/<version>/ois.schema.json` | `../schema/ois.schema.json`, published by `scripts/publish-schema.mjs` at the path its `$id` names |
| `/llms.txt`, `/llms-full.txt`, `/llms-small.txt` | generated by `starlight-llms-txt` for AI agents |
| `/images/*.svg` | `public/images/`, hand-drawn diagrams |

`scripts/sync-content.mjs` generates the specification, community, conformance and profile pages
before every build and dev run; they are not committed, so edit their sources. The build fails on
a broken internal link (`starlight-links-validator`).

## Versioned URLs never change

`/schema/v0.1/…`, `/passport/v0.1/` and `/methods/basic-intent-coverage/v0.1/` are identifiers
that records refer to (RFC #6). Once published, their meaning does not change: a correction gets
a new version and a new URL.

The schema is published at the path its own `$id` names, so version 0.2 lands at
`/schema/v0.2/` next to 0.1 instead of replacing it, and the build fails if the published file
differs from `schema/ois.schema.json`. While the `$id` is still the placeholder
`https://ois.example/…`, nothing is published: the content will change with draft 5, and a
versioned URL must not. Until then the site links to the schema on GitHub.

Open point for when a second version exists: the build publishes only the current schema, so
older versions must be kept, for example as frozen copies in `public/schema/<version>/`.

## Hosting

GitHub Pages serves the site under the custom domain `openintentschema.io` with enforced HTTPS
(*Settings → Pages*, source "GitHub Actions"). DNS is at the registrar: the apex has GitHub
Pages' A and AAAA records and `www` a CNAME to `openintentschema.github.io`. The MX and SPF
records are the project's mail (editors@openintentschema.io) and must stay.

## Privacy

The site loads nothing from third parties: no web fonts, scripts, images or analytics from other
domains. Search runs in the browser on a local index. GitHub Pages, which serves the site, sees
the requests like any web server.
